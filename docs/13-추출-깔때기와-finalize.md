# 13. 식품(OFF) 추출 깔때기 전체와 finalize가 하는 일 (2026-08-05 실측 기준)

> English version: [`13-extraction-funnel-and-finalize.en.md`](13-extraction-funnel-and-finalize.en.md)

관련 문서: 07(덤프 처리 방법), 08(설계·함정 13개), 12(병렬화 속도). 이 문서는
"덤프 453만 행이 어떤 필터를 거쳐 코퍼스가 되는가"와 "finalize가 정확히 뭘
하는가"를 한눈에 모은 요약이다. §0~5의 수치는 2026-08-05 오전(CAND_CAP 20,000)
실측 스냅샷 — **최종 확정 수치는 §6** (같은 날 저녁, OFF 완전 소진).

## 0. 깔때기 한눈에

| 단계 | 개수 | 거르는 것 | 네트워크 |
|---|---|---|---|
| OFF CSV 덤프 전체 | 4,535,553행 | — | 없음(로컬 파일) |
| ① scan: 기본 필터 | 93,815 (+기선정 1.1만 = 총 ~10.5만) | 아래 §1의 5종 | 없음 |
| ② 스캔 수 상위 CAND_CAP | 20,000 | 품질 아닌 물량 캡(인기순) | 없음 |
| ③ snapshot: 영어 라벨 | 16,150 (81%) | JSONL 덤프의 `lang` ≠ en | 없음 |
| ④ select: 게이트+생존 | 라운드당 500씩 소비 | 아래 §3의 4종 + 이미지 생존 | 이미지 HEAD만 |
| ⑤ finalize 빌드 게이트 | 탈락 1~3% | 페이지 재료(선택 항목) 3개 미만 | 이미지 다운로드 |

API는 식품 경로에서 **전혀 안 쓴다**(검색 API 사망으로 덤프 전환, docs/07).
네트워크는 ④의 생존 확인(HEAD)과 ⑤의 이미지 다운로드뿐 — 그래서 이 둘만
병렬화했다(docs/12).

## 1. ① scan — CSV 453만 행 → ~10만 (기본 필터 5종)

CSV를 한 줄씩 읽으며(메모리 몇 MB) 다음을 모두 만족해야 통과:

1. **영어권 시장**: `countries_en`에 미·영·아일랜드·호주·캐나다·뉴질랜드 중 하나 포함
   (판매국 기준 프리필터 — 라벨 언어의 최종 판정은 ③에서 별도로 함)
2. **영양라벨 사진 있음**: `image_nutrition_url` 존재
3. **원재료 텍스트 있음**: `ingredients_text` 존재
4. **바코드 유효**: 체크숫자 검증 통과 + 이미 선정된 제품 제외
5. **영양 수치 8칸 이상**: `*_100g` 컬럼(조리 후 제외) 채워진 수 ≥ 8

## 2. ②③ 물량 캡과 언어 판정

- 통과분을 **스캔 수(unique_scans_n, 소비자가 앱으로 찍은 횟수) 내림차순**으로
  정렬해 상위 CAND_CAP(현재 20,000)만 후보로 저장. 인기 제품일수록 데이터가
  알차다는 경험칙. 풀이 마르면 CAND_CAP을 올려 재스캔한다(5천→1만→2만 이력).
- 13GB JSONL 덤프를 1회 순회하며 후보의 전체 레코드(스냅샷 필드 36종)를 추출,
  이때 `lang` 필드로 **라벨 언어를 최종 판정** — en만 쇼트리스트에 남김.
  실측 영어율: 상위 5천 구간 ~80% → 2만 구간에서도 81%로 유지.

## 3. ④ select — 라운드마다 500개 선별

쇼트리스트를 점수순으로 훑으며 아래 게이트를 통과한 것만 담는다:

1. **영양 as-sold 7칸+**: 스냅샷의 `nutriments` 중 조리-후(prepared) 제외 `_100g` 키 ≥ 7
2. **카테고리 정상**: `en:null` 태그 제품 제외
3. **중복 제거**: (브랜드+제품명) 정규화 키가 기존 선정분·이번 라운드와 겹치면 제외
   (브랜드가 다르면 동명 허용)
4. **이미지 생존**: 영양라벨 사진이 HEAD 응답 정상이어야 함(필수).
   정면·원재료 사진은 죽어 있으면 제품을 버리는 대신 **그 사진만 빼고** 진행
   → 검수 리포트의 "이미지 3장 미만" 항목으로 집계됨

통과분을 selection.yaml·배치 목록(day-NN-entities.txt)에 append. 여기까지는
명단 등록일 뿐 코퍼스가 아니다.

## 4. ⑤ finalize — 명단을 코퍼스로 (체크포인트마다 1회)

`python -m scripts.bulk_expand finalize --batch day-NN` 이 순서대로 실행:

| 단계 | 하는 일 | 실측(1.1만 엔티티) |
|---|---|---|
| extract_facts | 스냅샷 → 원자 팩트(facts.jsonl)·엔티티 맵 재생성. 전 클래스(식품·장소·의약품) 전체를 매번 다시 뽑는다(결정적·멱등) | ~5분 |
| build_fixtures | **게이트**(필수 페이지 + 선택 항목 3개 미만이면 탈락) → 엔티티마다 HTML 페이지 4템플릿 순환 생성 + linkset.json + 이미지 다운로드(미보유분만, 동시 8 프리페치) → manifest | 페이지는 ~10분, 이미지는 신규량에 비례 |
| build_fixtures --overrides | 같은 것을 조작본(counterfactual) 오버라이드 적용해 counterfactual/ 트리에 한 벌 더(이미지는 복사) | ~5분 |
| validate | 무결성 7종: 스키마, 팩트-페이지 배치 실존, 정답 값이 페이지에 실제 존재, 중복·모호성, 조작본 발산 등 | 58초 |
| verify_batch | 페이지 재생성 비교(같은 입력→같은 출력) + 정체불명 폴더 검사 | 18초 |
| make_review | 사람 검수용 리포트(work/expansion/day-NN/entity-review.md): 표기 상이·이미지 부족·라이선스·분포 편중 | 초 단위 |

- 게이트 탈락(GATE FAIL)·예외(BUILD FAIL)는 끝에 명단으로 출력되고 종료 코드 1
  — 탈락자를 selection에서 빼고 재실행하면 된다(빌드는 엔티티 단위 오류 격리,
  탈락자는 폴더 잔재를 남기지 않음).
- 운영 방식(2026-08-04 합의): 라운드마다는 select까지만, finalize는 **2,000개마다
  체크포인트**로 실행.

## 6. 최종 결과 (2026-08-05 저녁 확정 — OFF 종결)

CAND_CAP을 1만→2만→4만→8만으로 올려 재스캔 3회, 선별 라운드 총 152회로
**기본 필터를 통과하는 OFF 제품 전체를 소진**했다. 깔때기 최종 집계:

| 단계 | 개수 |
|---|---|
| OFF CSV 덤프 전체 | 4,535,553 |
| 기본 필터 5종 통과 | **~105,500** |
| 영어 라벨 (78~81%, 전 구간 유지) | ~85,000 |
| 선별 게이트 통과·선정 (영양 7칸·중복·이미지 생존) | 80,240 |
| 빌드 게이트 통과 = **최종 식품 코퍼스** | **75,197** |

**확정 코퍼스 (validate 전 검사·verify_batch 통과):**

- 엔티티 **75,471** (식품 75,197 / 장소 254 / 의약품 20)
- 팩트 **1,880,481** / 페이지 487,954 / 이미지 211,516 (+조작본 코퍼스 1벌)
- 사람 검수 항목: 이미지 3장 미만 14,637(정면·원재료 사진 사망분 — 영양라벨은
  전원 보유), 팩트 서식 잔재 8건, 모호 팩트 175,018(QA 골드 제외 목록 자동 관리)
- 8만 규모 finalize 실측: **7분** (docs/14의 수리 이후; 수리 전 방식이면 ~8시간 추정)

식품 축은 이것으로 **종결** — 더 뽑으려면 기준 완화(비영어 라벨 허용 등)가 필요하며
권장하지 않는다. 남은 확장 여지는 장소(Tour, day-09)와 의약품 대량 편입뿐.
