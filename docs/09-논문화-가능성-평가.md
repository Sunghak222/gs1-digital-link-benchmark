# 09 — 논문화 가능성 평가 (벤치마크 데이터셋 논문)

> 작성: 2026-07-23 · 방법: 웹 심층 조사(출처 21건 수집, 주장 104건 추출, 상위 25건을 3표 교차검증 — 25건 전부 확정) + 우리 벤치마크 실측 수치 대조.
> 검증 확정된 근거는 **NeurIPS 트랙 공식 정책(2025·2026)과 CRAG 논문 원문**이고, 그 외 비교 논문 수치는 원문 1회 확인(단일 출처)임을 구분해 표기한다.

---

## 0. 결론 먼저

**지금 상태로는 상위 학회에 못 낸다. 그러나 구조적 결함이 아니라 "양"의 문제라서, 6개월~1년 보강하면 현실적인 도전이 된다.**

- **설계(질)는 이미 논문감이다** — 과제 프레이밍이 선행 벤치마크에 없는 자리이고(§3), 구축 방법론(단일 원천 유도, CF 쌍대 말뭉치, 코드화된 품질 게이트)은 2026년부터 NeurIPS가 표방하는 "평가 자체를 과학으로" 방향과 정확히 맞물린다(§2).
- **규모·증거(양)가 결정적으로 부족하다** — QA 221개(수용작의 1/6~1/20), 평가 시스템 1개(수용작은 6~8개+), 자기 시스템 정확도 83~87%(난이도 여유 부족 신호), 검수 일치율(IAA) 미보고(§4).
- 현실적 경로: **1차 타깃 SIGIR/TheWebConf 리소스 트랙 또는 LREC**(규모 부담이 덜하고 자원·재현성 강조가 우리 강점과 맞음) → 보강이 잘 되면 **NeurIPS 2027 Evaluations & Datasets 트랙**(2026 마감은 이미 지남: abstract 5/4)(§5).

## 1. 상위 학회가 실제로 요구하는 것

NeurIPS의 데이터셋 트랙은 2026년부터 **Evaluations & Datasets(E&D) 트랙**으로 개편됐다(구 Datasets & Benchmarks). 공식 문서 기준으로 요구사항은 두 층이다. *(이 절 전부 3표 검증 확정)*

**① 형식 요건 — 기계적으로 충족 가능, 미충족 시 데스크 리젝**

| 요건 | 내용 |
|---|---|
| Croissant 메타데이터 | 기계가 읽는 데이터셋 명세 파일. 2026년부터 Responsible AI 필드(한계·편향·민감정보·출처)까지 필수. HF/Kaggle/Dataverse/OpenML에 올리면 자동 생성 |
| 심사 시점 접근성 | **투고 시점에** 리뷰어 전원이 요청 없이 데이터·코드에 접근 가능해야 함 (비공개 미리보기 URL 허용) |
| 공개 시한 | 카메라레디까지 완전 공개. 불이행 시 프로시딩 제외 가능 |
| 코드 공개 | 기여의 본체가 "재사용 가능한 실행물"(벤치마크 스위트·생성기)이면 코드 공개 의무 — 우리가 정확히 이 경우 |
| 호스팅 | 지정 4곳(Harvard Dataverse·Kaggle·HF·OpenML)이 사실상 표준 — 2025년 수용작의 80%+가 사용 |

**② 심사 기준 — 명시적 하한선은 없다**

공식 가이드라인에 **최소 QA 개수·베이스라인 개수·검수 일치율 기준은 없고**, "베이스라인을 이기는 것도 요구하지 않는다"고 명시돼 있다. 심사는:

- **Quality**: 과제 설계·문항 선정·평가 셋업의 엄밀성. **포화(saturation) 문제를 다뤘는지**, 평가 프로토콜의 통계적 건전성
- **Originality**: 새로운 과제 설계·평가 셋업만으로 성립 가능
- **Significance**: "의미 있는 공백을 메우는가 **또는** 방법 간 신뢰할 수 있는 비교를 가능하게 하는가" (둘 중 하나면 됨 — 단일 시스템 평가는 후자를 못 보여주므로 전자에 걸어야 함)

즉 **형식 기준으로는 우리 221개도 실격이 아니다.** 진짜 기준은 다음 절의 "수용작들이 실제로 한 것"이다.

## 2. 수용된 벤치마크들의 실측 수치 vs 우리

|---|---|---|---|---|
| **CRAG** (NeurIPS'24 D&B) ✓검증 | 4,409개 · 5도메인 · 8문항유형 · 인기도 층화 | LLM 8종 × (단독+RAG 3구성) + 상용 RAG 5종 수동채점 | 2단계 검수, 2인 독립 검토 **일치율 90%/94% 보고**, 3자 조정 | 최고 시스템 44~63% (여유 큼) |
| MRAG-Bench (ICLR'25) | 1,353개 + 이미지 16,130장 | (다수 VLM) | 전수 사람 주석 | — |
| MultiHop-RAG | 2,556개 (전부 멀티홉) | (다수) | — | — |

| ConflictBank (NeurIPS'24 D&B) | QA 553,117개 (지식충돌 특화) | (다수) | — | — |
| **우리 (현재)** | **221개** · 2도메인 · 이미지 11 · 멀티홉 5 | **1개 (자체 파이프라인)** | 전수 검수했으나 **1인, 일치율 미보고** | **자체 시스템 83~87% (여유 작음)** |

*(CRAG 행만 3표 검증 확정, 나머지 비교 논문 수치는 원문 단일 확인. CRAG는 Meta 지원 + 사내 언어학자 팀이 만든 상한선급 사례라는 점도 감안할 것.)*

격차를 숫자로: QA는 수용작 최소선(MRAG-Bench 1,353) 대비 **1/6**, 표준적 기대(CRAG 4,409) 대비 **1/20**. 평가 시스템 수는 **1 vs 6~13**. 이것이 "지금 못 내는 이유"의 전부이고, 반대로 말하면 **이 두 축을 채우면 낼 수 있다.**

## 3. 신규성 — 우리 자리가 정말 비어 있나

조사에서 확인된 것 *(각 원문 확인, 부정 증명 특성상 "못 찾음"이지 "없음 확정"은 아님)*:

- **GS1 공식 리졸버 테스트 스위트**: 프로토콜 적합성 검사 도구일 뿐, QA·RAG 평가 데이터셋이 아님 — GS1 Digital Link를 다루는 평가 벤치마크는 우리 것 외에 확인되지 않음
- **Amazon ESCI**(대표적 상품 데이터셋): 검색 관련성 벤치마크로 바코드·리졸버·QA 요소 없음
- "바코드 → 링크셋 → 문서 순회"라는 **구조화된 링크 내비게이션 RAG** 프레이밍의 기존 벤치마크는 발견되지 않음

추가 강점: 구축 방법론 자체가 기여가 된다. **팩트 단일 원천에서 말뭉치·정답지·CF를 동시 유도해 "정답지와 말뭉치가 어긋날 수 없음을 구성적으로 보장"** 하는 방식, LLM을 5개 지점에 앵커링(원문 재탐색 강제)한 준자동 구축, 품질 게이트의 코드화는 E&D 트랙이 2026년부터 내건 "평가의 과학화" 서사에 정확히 부합한다. CF 쌍대 말뭉치로 사전지식 응답을 탐지하는 설계는 지식충돌 연구 계보(Longpre'21, ConflictBank 등)에 접속되므로 관련연구 절도 자연스럽게 쓸 수 있다.

**리스크**: 도메인이 2개(식품·한국 관광지)뿐이고 장소 GLN이 가상이라, "GS1 생태계 일반"으로 주장을 넓히면 공격받는다. 주장 범위를 "실존 표준(GS1 DL + RFC 9264)의 충실한 시뮬레이션"으로 정확히 긋는 게 안전하다.

## 4. 결정적 격차 5개와 보강량

우선순위 순. ①②가 당락을 가르고, ③④⑤는 리뷰 방어력이다.

**① 평가 시스템 다양화 (1 → 6개 이상) — 최우선, 상대적으로 싸다**
자체 파이프라인 하나로는 Significance의 "방법 간 비교" 프롱을 통째로 포기하게 된다. 필요한 것: LLM 단독(폐쇄북) / 순정 RAG(벡터 검색만) / 링크셋 순회형(우리 방식) × LLM 3~4종(GPT·Claude·오픈소스 1~2). 우리 평가 시스템이 이미 있으므로 어댑터 작업이 주 비용. **여기서 "링크셋 구조를 활용하는 시스템이 순정 RAG보다 얼마나 나은가"가 나오면 그 자체가 논문의 핵심 결과가 된다.**

**② QA 확장 (221 → 1,500~3,000) — 가장 오래 걸린다**
엔티티는 이미 694개(계속 증가)라 재료는 충분하다. 병목은 검수. 현행 "초안 LLM 생성 → 사람 전수 검수" 루틴으로 엔티티당 3~4문항이면 2,000+가 나온다. 이때 **2인 독립 검수 + 일치율 보고 + 불일치 3자 조정**(CRAG 프로토콜)을 처음부터 설계에 넣어야 한다 — 나중에 소급 못 한다.

**③ 난이도 여유 확보 — 포화 심사 기준 대응**
자체 시스템이 이미 83~87%면 "금방 포화될 벤치마크"로 읽힌다(CRAG는 최고가 63%). 대응: (a) 멀티홉 비중 확대(현재 5개 → 수백), (b) 이미지 전용 증거 모드(HTML 우회 차단 — doc 04에 이미 설계됨), (c) CF 말뭉치 성적을 주 지표로(원본보다 어려움), (d) 엔티티 인기도 층화(유명/무명)로 난이도 축 추가. ①의 약한 베이스라인들이 낮은 점수를 깔아주는 효과도 있다.

**④ CF·이미지·멀티홉의 v1.0 한정 해소**
CF 102팩트/이미지 QA 11개/멀티홉 5개는 "구색" 수준으로 보인다. 확장 엔티티까지 CF 오버라이드 생성(현재 이월 과제), 이미지 QA를 장소 사진·정면/성분 사진으로 확대, 멀티홉 전역 재생성. 각각 파이프라인이 이미 있어 실행 비용 위주.

**⑤ 아티팩트 정비 — 기계적, 마지막에**
HF Datasets 호스팅 + Croissant(RAI 필드 포함) + 데이터시트 + 라이선스 정리(OFF는 ODbL, TourAPI 사진은 공공누리 1유형이라 재배포 가능 — 이미 게이트로 보장, 강점) + 평가 하네스 공개 리포지토리.

## 7. 조사의 한계 (정직 고지)

- 3표 검증을 통과한 근거는 NeurIPS 정책과 CRAG뿐. MRAG-Bench·MultiHop-RAG·RGB·ConflictBank·SIGIR 트랙 수치는 원문 1회 확인.
- ACL/LREC/WebConf 리소스 트랙의 구체 요구치는 미해결 — 투고처 확정 시 해당 CFP 직접 확인 필요.
- "GS1 벤치마크 부재"는 못 찾았다는 것이지 없음의 증명이 아님 — 투고 직전 재검색 필요.
- 우리 쪽 수치(221·83~87%·1시스템)는 2026-07-23 기준이며 확장 진행에 따라 변한다.
