# 05 — 실험 규모·비용·시간 계획

> 작성: 2026-07-13. 근거: E1 파일럿 5문항 실측 (run 폴더 `results/20260713-1343_pilot/`).
> 설계 배경은 doc 04. 이 문서는 "실험 전체를 돌리면 LLM을 몇 번 부르고, 몇 달러 들고,
> 몇 시간 걸리나"에 답한다. **모든 수치는 본실험 전 파일럿 재실측으로 갱신한다** (§5).

## 0. 이 문서의 결정 사항

- **멀티홉 5문항은 hit 실험에서만 돌린다** (2026-07-13 결정).
  이유: 멀티홉 질문에는 스캔한 상품이 없어(digital_link_path 없음) external 경로가
  구조적으로 건너뛰어지고, 억지로 상품 하나를 붙여도 검색 범위가 그 상품의 linkset으로
  잠긴다(vector_retriever.py:197). 여러 엔티티에 걸친 정보는 문서 경로로는 못 모으고
  KG로만 풀린다. → miss 실행은 single-hop 216문항, hit 실행은 221문항 전체.
  (miss에서 멀티홉을 맞히면 오히려 사전지식으로 답했다는 신호 — 원하면 건전성 체크로만.)
- **변조본 실행은 발산 대상 72문항만 돌린다** (2026-07-13 결정, doc 04 §4.3).
  근거 팩트가 변조되지 않은 문항(대조군)은 돌리지 않는다 — 판정이 기계적 값 대조 위주라
  답변 흔들림의 영향이 작다고 보고, 기준선 없이 가는 대신 보고서에 한계로 명시한다.
- **용어**: 변조본에서도 실세계 값을 답하는 실패는 "leak" 대신 **사전지식 활용**이라 부른다.
- **메인 실험은 3개다** (2026-07-13 결정): ③-a miss×원본, ③-b miss×변조본(발산 대상 72),
  ④ hit×원본. 캐시 빈 상태 측정(⑤)과 시간 통계용 반복 실행은 **선택 항목** — 논문에
  첫 스캔 속도 수치가 필요해지면 그때 돌린다.

## 1. 문항 1개의 단가 (파일럿 실측 + 가정)

| 경우 | LLM 호출 | 입력 토큰 | 출력 토큰 | 시간 |
|---|---|---|---|---|
| miss 1문항, **fast 실행 (③-a 216문항 본실행 실측, 에이전트 정상)** | 4.9회 | 17.5k | 0.45k | p50 6.3초 / p95 12.7초 / 최대 44초 |
| miss 1문항, full 실행 (파일럿 실측 — 에이전트 죽은 상태였음, 참고용) | 6회 | ~10k | ~0.3k | 평균 ~7초 |
| hit 1문항 (추정: 짧은 경로 4노드) | ~3회 | ~4k | ~0.3k | ~5초 |
| hit인데 critic이 KG답 거부 → external행 (20% 가정) | miss와 동일 | | | ~11초 |
| 채점 1문항 (LLM judge) | 1회 | ~1.2k | ~0.15k | ~2초 |

**fast 실행** (`run_eval.py --fast-miss`): miss에서 결말이 정해진 KG 헛걸음 구간
(질의정리→KG조회→합성1→critic_1)을 건너뛰고 문서 경로부터 돈다. 건너뛴 구간의 시간
**α = 평균 3.1초** (파일럿 5문항 실측, 2.0~4.7초 + 최초 호출 7.1초)를 TTFA 보고 때
상수로 보정한다. 주의 둘: ① 그 구간의 호출들은 프롬프트가 짧아 **비용 절감은 작다**
(문항당 입력 −1.6k, 전체 −$0.3 수준) — fast의 주 이득은 시간이다. ② critic_1의
조기종료 진단(doc 04 §4.4)은 fast에서 관측 불가 → 빠른 점검 30문항은 full로 돌려 겸한다.

- DL 에이전트 수리 완료(2026-07-13, max_completion_tokens) 후 본실행으로 실측 확정 —
  에이전트 포함 문항당 입력이 ~17.5k로 늘었고, 재시도 발생은 216문항 중 4건뿐(최대 44초).
- 임베딩(text-embedding-3-large) 비용은 전부 합쳐 $0.05 미만 → 이하 생략.
- 이미지 설명(VLM)은 후보 선택기가 사진을 고를 때만 발생하고, 한 번 만든 설명은 캐시에
  저장돼 재사용되므로 소액.

## 2. 실험 전체 규모

**메인 실험 3개 + 채점:**

| 실행 | 문항 | 입력 토큰 | 출력 토큰 | 시간 (직렬) |
|---|---|---|---|---|
| ③-a miss × 원본 (fast) — **✅ 실행 완료 (실측)** | 216 | 3.78M | 0.10M | **26분** |
| ③-b miss × 변조본 (fast, 발산 대상만) | 72 | ~1.3M | ~0.03M | ≈ **9분** |
| ④ hit × 원본 (멀티홉 5 포함, full) | 221 | ~1.6M | ~0.10M | 221 × ~6.5초 ≈ **24분** |
| 채점 (miss원본 216 + hit 221) | 437회 | ~0.5M | ~0.07M | ≈ **15분** (병렬화 가능 — 시간 측정과 무관) |
| **메인 소계** | 509문항 + 채점 437회 | **~7.2M** | **~0.30M** | 실행 **~59분** + 채점 15분 |

변조본 실행은 LLM 채점이 없다 — 원본 run과의 답 비교는 기계적 대조(compare_runs.py).

**선택·개발 비용 (메인 외):**

| 항목 | 문항 | 입력 토큰 | 출력 토큰 | 시간 |
|---|---|---|---|---|
| (선택) 캐시 빈 상태 측정 — 서비스 첫날의 "처음 스캔" 속도 재현 (엔티티 2~3개) | ~20 | 0.3M | 0.01M | 사진 설명을 현장 생성 → ~15초/문항 ≈ **7분** |
| 개발 중 빠른 점검 (30문항 × ~5회, **full** — 조기종료 진단·α 실측 겸용) | 150 | 2.4M | 0.09M | 회당 ~6분, 누적 ≈ **28분** (개발 기간에 분산) |

**총합 (메인 + 선택 + 개발)**: ~680문항 + 채점 437회, 입력 ~8.9M / 출력 ~0.43M 토큰.

## 3. 비용

단가 (OpenAI 공식 가격표, 2026-07-13 확인): **gpt-5.4-mini 입력 $0.75 / 출력 $4.50 /
캐시된 입력 $0.075** per 1M 토큰.

| | 계산 | 금액 |
|---|---|---|
| ③-a 실측 (완료) | 3.78M×$0.75 + 0.10M×$4.50 | **$3.28** (정가 기준) |
| 메인 실험 3개 + 채점 | 7.2M×$0.75 + 0.30M×$4.50 | **≈ $6.8** |
| 선택(캐시 빈 상태) + 개발 점검 포함 총액 | 9.9M×$0.75 + 0.40M×$4.50 | **≈ $9.2** |

- 처음 가정($0.25/$2.00)보다 입력 3배·출력 2.25배 비싸서 견적이 올랐다. 그래도 $10 미만.
- **실비는 이보다 낮을 가능성이 높다**: OpenAI가 반복되는 프롬프트 앞부분(시스템 프롬프트 등)을
  자동으로 캐시해 입력의 상당분을 1/10 가격($0.075)으로 청구한다. 같은 프롬프트 틀로 수백
  문항을 돌리는 우리 패턴에 유리 — 파일럿 재실측 때 실청구액으로 확인.
- LLM 호출 횟수: 메인 ~2,500회, 선택·개발 포함 ~4,100회.
- fast 실행의 비용 절감은 ~$0.8 수준(§1) — 비싼 프롬프트(후보 선택·합성·critic_2)가
  전부 문서 경로에 있기 때문. 추가 절감 지렛대: 채점 모델을 더 싼 걸로(어차피 파이프라인과
  다른 모델 권장), 개발 점검 반복 횟수 절약.

## 4. 총 시간

**메인 실험 3개 한 번 통과 = 약 1시간** (29+10+24분, 직렬 — 시간 측정 오염 방지 때문에
병렬 금지) **+ 채점 15분**. 개발 중 빠른 점검까지 전부 합치면 **약 1시간 45분**.

선택 항목 (필요해지면 추가):
- 캐시 빈 상태 측정: +7분
- 시간 통계(p50/p95) 안정화용 반복: miss×원본 fast 재실행 1~2회(+29~58분) —
  정확도·CF 판정은 1회분으로 끝난다.
- 변조본 run 병렬화는 규모가 72문항으로 준 뒤로는 이득(~7분)이 작아 보류.

주의: 사람이 붙어 있는 시간이 아니라 기계가 도는 시간이다. run은 중간에 끊겨도
results.jsonl이 문항 단위로 쌓이므로 이어서 돌릴 수 있다.

## 5. 실행 순서와 체크포인트 (돈 쓰기 전 확인 지점)

1. **DL 에이전트 수리** (팀) → **파일럿 5문항 재실측** → §1 표를 확정치로 갱신
2. 빠른 점검용 30문항 선정 — 무작위가 아니라 **자리를 정해 뽑는다**:
   hard 9문항 전부 + 사진 문항 + 글자 인코딩이 특이한(EUC-KR) 페이지 문항 +
   언어 교차 문항 + 나머지 easy. "시험이 너무 쉬운가?"의 1차 판정도 여기서.
3. 갱신된 단가 × §2 규모로 견적 재계산 → **본실험 승인**
4. 메인 실험 ③-a → ③-b → ④ 순서로 실행 (④는 ingest_kg.py와 KG 매핑표 팀 리뷰가
   선행 조건, doc 04 §2.1). 캐시 빈 상태 측정은 논문에 첫 스캔 속도가 필요할 때만.
